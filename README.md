## О дисциплине

В рамках дисциплины изучаются принципы проектирования и реализации интерфейсов прикладного программирования (API) для корпоративных информационных систем и сервисов с элементами машинного обучения:

- **Бизнес-архитектура и контракты:** декомпозиция предметной области, выявление внешних и внутренних потребителей, описание ресурсов в виде устойчивых сущностей.
- **Спецификации OpenAPI (Swagger):** формализация эндпоинтов, проектирование схем данных, определение HTTP-методов, заголовков и статус-кодов.
- **Интеграционные сценарии:** связывание пользовательских интерфейсов, внешних контрагентов и микросервисов инференса моделей машинного обучения.

## Assignment Workflow & Engineering Standards

Для каждого практического занятия в каталоге `tasks/` отводится отдельная папка по единому формату `tasks/<номер>_<тема>`, оформляемая по регламенту:

1. **Requirements Modeling:** Выделение границ системы, определение внешних и внутренних потребителей сервиса.
2. **Resource-Oriented Design:** Описание ресурсов исключительно в виде существительных (устойчивых сущностей предметной области) без процедурного смещения.
3. **Contract-First Approach:** Проектирование интерфейсов, путей (маршрутов) и схем данных до написания программного кода сервера.
4. **Traceability:** Обеспечение строгой трассируемости между контекстной схемой потоков данных и спецификацией API.
5. **Artifact Delivery (PDF Export):** Формирование итогового отчета в формате Markdown (`README.md`) с последующим экспортом в `README.pdf` для сдачи на проверку.
6. **Git Standards:** Фиксация выполненных этапов по стандарту Conventional Commits (`feat:`, `docs:`, `chore:`).
